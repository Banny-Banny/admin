# 🛠 Spec Kit 기반 AI 협업 가이드

우리 팀은 GitHub Spec-Kit 워크플로우를 사용하여 AI와 함께 체계적으로 기능을 개발합니다. 모든 기능 구현은 아래 4단계를 따릅니다.

## 🚀 개발 프로세스

### 1️⃣ 사양 정의 (Specification)
- **명령어**: `/speckit.specify`
- **목적**: '무엇'을 '왜' 만드는지 정의합니다.
- **활동**: AI가 생성한 `spec.md`를 검토하며 사용자 요구사항이 충족되었는지 확인합니다.

### 2️⃣ 기술 계획 (Technical Plan)
- **명령어**: `/speckit.plan`
- **목적**: 기술 스택, 아키텍처, 폴더 구조를 설계합니다.
- **활동**: 프로젝트 규칙(React, Tailwind 등)이 반영된 `plan.md`를 확정합니다.

### 3️⃣ 작업 분해 (Task Breakdown)
- **명령어**: `/speckit.tasks`
- **목적**: 설계를 구현 가능한 작은 단위(Task)로 쪼갭니다.
- **활동**: 독립적으로 테스트 가능한 수준으로 작업이 나뉘었는지 검토합니다.

### 4️⃣ 실제 구현 (Implementation)
- **명령어**: `/speckit.implement` (또는 에이전트에게 직접 지시)
- **목적**: 확정된 Task를 바탕으로 실제 코드를 작성합니다.
- **활동**: AI가 짠 코드를 리뷰하고 빌드 오류를 함께 수정합니다.

## ⚠️ 주의사항 (중요!)
1. **에이전트 모드 사용**: 반드시 Cursor의 **Agent 모드**에서 실행해야 파일 생성 및 수정이 가능합니다.
2. **Accept 필수**: AI가 생성한 모든 설정 파일은 화면상의 **[Accept]** 버튼을 눌러야 실제 파일로 저장됩니다.
3. **보안 주의**: `.cursor/` 폴더 등 인증 정보가 포함될 수 있는 폴더는 `.gitignore`에 등록되어 있는지 확인하세요.
