## User Scenarios & Testing *(mandatory)*

### User Story 1 - 문의 목록 조회 및 검색 (Priority: P1)

관리자가 문의하기 페이지에서 고객 문의 목록을 조회하고, 검색어나 필터를 사용하여 원하는 문의를 찾을 수 있어야 합니다. 문의 목록은 HTTP 통신을 통해 백엔드 API에서 조회합니다.

**Why this priority**: 문의 목록 조회는 관리자가 고객 문의를 확인하고 관리하는 첫 단계입니다. 이 기능 없이는 관리자가 어떤 문의가 있는지 파악할 수 없습니다.

**Independent Test**: 관리자가 문의하기 페이지에 접속하여 문의 목록을 확인하고, 검색어를 입력하거나 상태/우선순위 필터를 적용하여 원하는 문의를 찾는 것을 테스트할 수 있습니다. 이 기능만으로도 관리자가 문의를 파악하고 탐색할 수 있는 최소한의 가치를 제공합니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 문의하기 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** HTTP API를 통해 최근 문의 사항 목록이 조회되고 표시되며 각 문의의 제목, 내용, 고객 정보, 상태, 우선순위, 시간 정보가 표시됩니다.
2. **Given** 관리자가 문의 목록을 확인한 상태, **When** 검색어를 입력하면, **Then** 고객명, 제목, 내용에 검색어가 포함된 문의만 필터링되어 표시됩니다.
3. **Given** 관리자가 문의 목록을 확인한 상태, **When** 상태 필터(대기중, 처리중, 완료)를 선택하면, **Then** 해당 상태의 문의만 필터링되어 표시됩니다.
4. **Given** 관리자가 문의 목록을 확인한 상태, **When** 우선순위 필터(긴급, 보통, 낮음)를 선택하면, **Then** 해당 우선순위의 문의만 필터링되어 표시됩니다.
5. **Given** 관리자가 문의 목록을 확인한 상태, **When** 검색어와 필터를 동시에 적용하면, **Then** 두 조건을 모두 만족하는 문의만 표시됩니다.
6. **Given** 관리자가 문의 목록을 확인한 상태, **When** 문의가 한 페이지에 표시할 수 있는 개수보다 많으면, **Then** 페이지네이션이 표시되고 페이지를 이동할 수 있습니다.

### User Story 2 - 문의 상세 조회 및 채팅 (Priority: P1)

관리자가 문의 목록에서 특정 문의를 선택하여 상세 정보를 확인하고, 채팅 인터페이스를 통해 고객과 소통할 수 있어야 합니다. 채팅 메시지는 WebSocket을 통해 실시간으로 주고받습니다.

**Why this priority**: 문의 상세 조회 및 채팅은 관리자가 고객 문의에 응답하는 핵심 기능입니다. 이 기능 없이는 관리자가 고객과 소통할 수 없습니다.

**Independent Test**: 관리자가 문의 목록에서 특정 문의를 클릭하여 채팅 인터페이스를 열고, 고객과의 대화 내역을 확인하며, 메시지를 입력하여 응답하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 문의 목록을 확인한 상태, **When** 특정 문의를 클릭하면, **Then** 채팅 인터페이스가 열리고 WebSocket 연결이 설정되며 해당 문의의 제목, 고객 정보, 초기 문의 메시지가 표시됩니다.
2. **Given** 관리자가 채팅 인터페이스를 확인한 상태, **When** 이전 대화 내역이 있으면, **Then** HTTP API를 통해 대화 내역을 조회하고 관리자와 고객의 메시지가 시간순으로 표시되며 발신자가 구분되어 표시됩니다.
3. **Given** 관리자가 채팅 인터페이스에서 메시지를 입력한 상태, **When** 전송 버튼을 클릭하거나 Enter 키를 누르면, **Then** 메시지가 WebSocket을 통해 전송되고 대화 내역에 추가되며 고객에게 실시간으로 전달됩니다.
4. **Given** 관리자가 채팅 인터페이스를 확인한 상태, **When** 고객이 새 메시지를 보내면, **Then** WebSocket을 통해 실시간으로 메시지가 수신되고 대화 내역에 추가되어 표시됩니다.
5. **Given** 관리자가 채팅 인터페이스를 확인한 상태, **When** 닫기 버튼을 클릭하면, **Then** WebSocket 연결이 종료되고 채팅 인터페이스가 닫히며 문의 목록으로 돌아갑니다.
6. **Given** 관리자가 채팅 인터페이스에서 메시지를 입력한 상태, **When** 메시지가 비어있으면, **Then** 전송 버튼이 비활성화됩니다.

### User Story 3 - 문의 상태 관리 (Priority: P2)

관리자가 문의의 상태를 변경하여 문의 처리 진행 상황을 관리할 수 있어야 합니다.

**Why this priority**: 문의 상태 관리는 관리자가 문의 처리 진행 상황을 추적하고 우선순위를 관리하는 데 도움이 됩니다.

**Independent Test**: 관리자가 문의의 상태를 변경하고, 변경된 상태가 문의 목록과 채팅 인터페이스에 반영되는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 문의 목록을 확인한 상태, **When** 문의의 상태가 변경되면, **Then** 문의 목록에서 상태 태그가 업데이트되어 표시됩니다.
2. **Given** 관리자가 채팅 인터페이스를 확인한 상태, **When** 문의 상태가 변경되면, **Then** 채팅 인터페이스에도 변경된 상태가 반영됩니다.
3. **Given** 관리자가 문의를 처리하기 시작한 상태, **When** 상태를 "처리중"으로 변경하면, **Then** 해당 문의가 처리중 상태로 표시됩니다.
4. **Given** 관리자가 문의 처리를 완료한 상태, **When** 상태를 "완료"로 변경하면, **Then** 해당 문의가 완료 상태로 표시됩니다.

---

### User Story 4 - 문의 우선순위 관리 (Priority: P2)

관리자가 문의의 우선순위를 확인하고 관리할 수 있어야 합니다.

**Why this priority**: 우선순위 관리는 관리자가 긴급한 문의를 우선적으로 처리할 수 있게 합니다.

**Independent Test**: 관리자가 문의 목록에서 우선순위를 확인하고, 우선순위별로 필터링하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 문의 목록을 확인한 상태, **When** 문의에 우선순위가 설정되어 있으면, **Then** 문의 목록에서 우선순위 태그가 표시됩니다.
2. **Given** 관리자가 문의 목록을 확인한 상태, **When** 우선순위 필터를 적용하면, **Then** 해당 우선순위의 문의만 표시됩니다.
3. **Given** 관리자가 긴급 문의를 확인한 상태, **When** 우선순위가 "긴급"으로 표시되면, **Then** 해당 문의가 시각적으로 강조되어 표시됩니다.

---

### Edge Cases

- 문의 목록이 비어있을 때 어떻게 표시할까요?
- 검색 결과가 없을 때 어떻게 표시할까요?
- 채팅 인터페이스에서 메시지 전송 중 네트워크 오류가 발생하면 어떻게 처리할까요?
- 동시에 여러 관리자가 같은 문의에 응답하려고 하면 어떻게 처리할까요?
- 페이지네이션에서 마지막 페이지를 넘어가면 어떻게 처리할까요?
- 문의 상태 변경 중 다른 관리자가 동시에 변경하면 어떻게 처리할까요?
- 채팅 메시지가 매우 길 때 어떻게 표시할까요?
- 채팅 인터페이스에서 새 메시지가 도착하면 어떻게 알림할까요?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자가 HTTP API를 통해 문의 목록을 조회할 수 있어야 합니다.
- **FR-002**: 시스템은 관리자가 문의 목록에서 검색어를 입력하여 문의를 검색할 수 있어야 합니다.
- **FR-003**: 시스템은 관리자가 문의 목록에서 상태 필터를 적용하여 문의를 필터링할 수 있어야 합니다.
- **FR-004**: 시스템은 관리자가 문의 목록에서 우선순위 필터를 적용하여 문의를 필터링할 수 있어야 합니다.
- **FR-005**: 시스템은 관리자가 검색어와 필터를 동시에 적용할 수 있어야 합니다.
- **FR-006**: 시스템은 관리자가 페이지네이션을 통해 문의 목록을 탐색할 수 있어야 합니다.
- **FR-007**: 시스템은 관리자가 문의 목록에서 특정 문의를 선택하여 채팅 인터페이스를 열 수 있어야 합니다.
- **FR-008**: 시스템은 관리자가 채팅 인터페이스에서 문의의 제목, 고객 정보, 초기 문의 메시지를 확인할 수 있어야 합니다.
- **FR-009**: 시스템은 관리자가 채팅 인터페이스에서 HTTP API를 통해 이전 대화 내역을 확인할 수 있어야 합니다.
- **FR-010**: 시스템은 관리자가 채팅 인터페이스에서 메시지를 입력하고 WebSocket을 통해 전송할 수 있어야 합니다.
- **FR-025**: 시스템은 WebSocket을 통해 실시간으로 새 메시지를 수신하고 표시할 수 있어야 합니다.
- **FR-026**: 시스템은 채팅 인터페이스가 열릴 때 WebSocket 연결을 설정하고, 닫힐 때 연결을 종료해야 합니다.
- **FR-011**: 시스템은 관리자가 채팅 인터페이스에서 Enter 키를 눌러 메시지를 전송할 수 있어야 합니다.
- **FR-012**: 시스템은 관리자가 채팅 인터페이스에서 Shift+Enter를 눌러 줄바꿈을 할 수 있어야 합니다.
- **FR-013**: 시스템은 관리자가 채팅 인터페이스에서 빈 메시지를 전송할 수 없도록 해야 합니다.
- **FR-014**: 시스템은 관리자가 채팅 인터페이스에서 닫기 버튼을 클릭하여 문의 목록으로 돌아갈 수 있어야 합니다.
- **FR-015**: 시스템은 관리자가 문의의 상태를 확인할 수 있어야 합니다.
- **FR-016**: 시스템은 관리자가 문의의 우선순위를 확인할 수 있어야 합니다.
- **FR-017**: 시스템은 문의 목록에서 각 문의의 상태를 시각적으로 구분하여 표시해야 합니다.
- **FR-018**: 시스템은 문의 목록에서 각 문의의 우선순위를 시각적으로 구분하여 표시해야 합니다.
- **FR-019**: 시스템은 문의 목록에서 각 문의의 고객 정보(이름, 이메일)를 표시해야 합니다.
- **FR-020**: 시스템은 문의 목록에서 각 문의의 시간 정보를 표시해야 합니다.
- **FR-021**: 시스템은 채팅 인터페이스에서 관리자와 고객의 메시지를 구분하여 표시해야 합니다.
- **FR-022**: 시스템은 채팅 인터페이스에서 각 메시지의 시간 정보를 표시해야 합니다.
- **FR-023**: 시스템은 문의 목록이 비어있을 때 적절한 메시지를 표시해야 합니다.
- **FR-024**: 시스템은 검색 결과가 없을 때 적절한 메시지를 표시해야 합니다.

### Key Entities

- **문의**: 고객이 관리자에게 보낸 문의 사항. 식별자, 고객 정보(이름, 이메일), 제목, 내용, 상태, 우선순위, 생성 시간 정보를 포함합니다.
- **메시지**: 채팅 인터페이스에서 주고받는 메시지. 식별자, 발신자(관리자/고객), 내용, 전송 시간 정보를 포함합니다.
- **문의 상태**: 문의의 처리 진행 상황. 대기중, 처리중, 완료 등의 값을 가질 수 있습니다.
- **문의 우선순위**: 문의의 중요도. 긴급, 보통, 낮음 등의 값을 가질 수 있습니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 문의하기 페이지에 접속하여 HTTP API를 통해 3초 이내에 문의 목록을 확인할 수 있습니다.
- **SC-002**: 관리자는 검색어를 입력하여 1초 이내에 필터링된 문의 목록을 확인할 수 있습니다.
- **SC-003**: 관리자는 필터를 적용하여 1초 이내에 필터링된 문의 목록을 확인할 수 있습니다.
- **SC-004**: 관리자는 문의를 클릭하여 2초 이내에 채팅 인터페이스를 열고 WebSocket 연결을 설정할 수 있습니다.
- **SC-005**: 관리자는 채팅 인터페이스에서 메시지를 입력하고 WebSocket을 통해 2초 이내에 전송할 수 있습니다.
- **SC-006**: 관리자는 채팅 인터페이스에서 HTTP API를 통해 이전 대화 내역을 2초 이내에 확인할 수 있습니다.
- **SC-011**: 관리자가 채팅 인터페이스를 사용 중일 때 고객이 새 메시지를 보내면 1초 이내에 실시간으로 표시됩니다.
- **SC-007**: 페이지네이션을 사용하여 목록을 탐색할 때 2초 이내에 다음 페이지가 로드됩니다.
- **SC-008**: 검색 및 필터링 기능 사용 시 95% 이상의 경우 1초 이내에 결과가 표시됩니다.
- **SC-009**: 문의 목록에서 각 문의의 상태와 우선순위가 100% 정확하게 표시됩니다.
- **SC-010**: 채팅 인터페이스에서 메시지가 100% 정확하게 표시되고 전송됩니다.

## Assumptions

- 관리자는 이미 인증 시스템(001-admin-auth)을 통해 로그인한 상태입니다.
- 백엔드 API가 문의 조회, 메시지 전송 등의 엔드포인트를 제공합니다.
- 문의 데이터와 메시지 데이터는 백엔드에서 관리됩니다.
- 관리자는 적절한 권한을 가지고 있습니다.
- 시스템은 반응형 디자인을 지원합니다.
- 브라우저는 최신 버전이며 JavaScript가 활성화되어 있습니다.
- 네트워크 연결이 안정적입니다.
- 문의는 고객이 생성하며, 관리자는 조회하고 응답할 수 있습니다.

## Dependencies

- 관리자 인증 시스템 (001-admin-auth): 관리자가 로그인하고 인증 상태를 유지하는 기능
- 백엔드 API: 문의 관련 REST API 엔드포인트 (HTTP 통신)
  - 문의 목록 조회 API (검색, 필터링, 페이지네이션 지원)
  - 문의 상세 조회 API
  - 문의 상태 변경 API
  - 메시지 목록 조회 API
