# Feature Specification: 유저 알림 메시지 발송 기능

**Feature Branch**: `003-notification-send`  
**Created**: 2026-01-16  
**Status**: Draft  
**Input**: User description: "@src/app/components/MarketingPage/index.tsx 에서 유저에게 알림으로 안내메시지를 발송할 기능을 만들 것임. 메시지 유형과 발송 대상은 type에 있는대로 설정해주면 됨. 제목과 내용은 무조건 글이 작성되어야 하고 미입력시 '즉시발송' 버튼이 비활성화 되어야함."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 즉시 알림 메시지 발송 (Priority: P1)

관리자가 유저에게 즉시 알림 메시지를 발송할 수 있어야 합니다. 메시지 유형(광고, 안내, 이벤트, 업데이트)과 발송 대상(전체 회원, 활성 회원, 휴면 회원, VIP 회원)을 선택하고, 제목과 내용을 입력한 후 즉시 발송할 수 있습니다.

**Why this priority**: 이는 기능의 핵심 사용 사례로, 관리자가 유저에게 즉시 알림을 보낼 수 있는 기본 기능입니다.

**Independent Test**: 관리자가 메시지 발송 폼에서 모든 필수 필드를 입력하고 즉시 발송 버튼을 클릭하여 메시지가 성공적으로 발송되는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 메시지 발송 페이지에 접근했을 때, **When** 메시지 유형을 선택하고 발송 대상을 선택하고 제목과 내용을 입력한 후 즉시 발송 버튼을 클릭하면, **Then** 메시지가 즉시 발송되고 발송 내역에 기록됩니다.

2. **Given** 관리자가 메시지 발송 폼을 작성 중일 때, **When** 제목이나 내용 중 하나라도 비어있으면, **Then** 즉시 발송 버튼이 비활성화 상태로 표시됩니다.

3. **Given** 관리자가 메시지 발송 폼을 작성 중일 때, **When** 제목과 내용 모두 입력되면, **Then** 즉시 발송 버튼이 활성화 상태로 표시됩니다.

4. **Given** 관리자가 메시지 유형을 선택하지 않았을 때, **When** 메시지 발송을 시도하면, **Then** 유효성 검사 오류가 표시되고 메시지가 발송되지 않습니다.

5. **Given** 관리자가 발송 대상을 선택하지 않았을 때, **When** 메시지 발송을 시도하면, **Then** 유효성 검사 오류가 표시되고 메시지가 발송되지 않습니다.

### User Story 2 - 메시지 유형 및 발송 대상 선택 (Priority: P1)

관리자가 메시지 유형과 발송 대상을 선택할 수 있어야 합니다. 메시지 유형은 광고, 안내, 이벤트, 업데이트 중에서 선택할 수 있고, 발송 대상은 전체 회원, 활성 회원, 휴면 회원, VIP 회원 중에서 선택할 수 있습니다.

**Why this priority**: 메시지 유형과 발송 대상 선택은 메시지 발송의 필수 구성 요소로, 이 기능 없이는 메시지를 발송할 수 없습니다.

**Independent Test**: 관리자가 메시지 유형 드롭다운과 발송 대상 드롭다운에서 각각 옵션을 선택하고, 선택된 값이 올바르게 표시되는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 메시지 발송 폼에 접근했을 때, **When** 메시지 유형 드롭다운을 클릭하면, **Then** 광고, 안내, 이벤트, 업데이트 옵션이 표시됩니다.

2. **Given** 관리자가 메시지 발송 폼에 접근했을 때, **When** 발송 대상 드롭다운을 클릭하면, **Then** 전체 회원, 활성 회원, 휴면 회원, VIP 회원 옵션이 표시됩니다.

3. **Given** 관리자가 메시지 유형을 선택했을 때, **When** 선택한 유형이 폼에 반영되면, **Then** 선택된 메시지 유형이 올바르게 표시됩니다.

4. **Given** 관리자가 발송 대상을 선택했을 때, **When** 선택한 대상이 폼에 반영되면, **Then** 선택된 발송 대상이 올바르게 표시됩니다.

### User Story 3 - 메시지 내용 입력 및 유효성 검사 (Priority: P1)

관리자가 메시지 제목과 내용을 입력할 수 있어야 하며, 제목과 내용은 필수 입력 항목입니다. 제목이나 내용이 비어있으면 즉시 발송 버튼이 비활성화되어야 합니다.

**Why this priority**: 메시지 내용 입력은 메시지 발송의 핵심 요소이며, 유효성 검사를 통해 빈 메시지 발송을 방지합니다.

**Independent Test**: 관리자가 제목과 내용 필드에 텍스트를 입력하고, 입력 상태에 따라 즉시 발송 버튼의 활성화/비활성화 상태가 변경되는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 메시지 발송 폼에 접근했을 때, **When** 제목 필드에 텍스트를 입력하면, **Then** 입력한 텍스트가 제목 필드에 표시됩니다.

2. **Given** 관리자가 메시지 발송 폼에 접근했을 때, **When** 내용 필드에 텍스트를 입력하면, **Then** 입력한 텍스트가 내용 필드에 표시됩니다.

3. **Given** 관리자가 제목 필드를 비워두었을 때, **When** 내용만 입력하면, **Then** 즉시 발송 버튼이 비활성화 상태로 유지됩니다.

4. **Given** 관리자가 내용 필드를 비워두었을 때, **When** 제목만 입력하면, **Then** 즉시 발송 버튼이 비활성화 상태로 유지됩니다.

5. **Given** 관리자가 제목과 내용 모두 입력했을 때, **When** 두 필드 모두에 텍스트가 있으면, **Then** 즉시 발송 버튼이 활성화 상태로 표시됩니다.

6. **Given** 관리자가 제목과 내용을 모두 입력한 후, **When** 제목이나 내용 중 하나를 삭제하면, **Then** 즉시 발송 버튼이 비활성화 상태로 변경됩니다.

### Edge Cases

- 제목이나 내용에 공백만 입력된 경우 어떻게 처리할까요? (공백만 있는 경우도 비어있는 것으로 간주해야 할까요?)
- 제목이나 내용의 최대 길이 제한이 있을까요?
- 메시지 발송 중 네트워크 오류가 발생하면 어떻게 처리할까요?
- 동시에 여러 메시지를 발송하려고 시도하면 어떻게 처리할까요?
- 발송 대상에 선택된 회원이 없을 경우 어떻게 처리할까요?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자가 메시지 유형을 선택할 수 있어야 합니다. 선택 가능한 유형은 광고, 안내, 이벤트, 업데이트입니다.

- **FR-002**: 시스템은 관리자가 발송 대상을 선택할 수 있어야 합니다. 선택 가능한 대상은 전체 회원, 활성 회원, 휴면 회원, VIP 회원입니다.

- **FR-003**: 시스템은 관리자가 메시지 제목을 입력할 수 있어야 합니다. 제목은 필수 입력 항목입니다.

- **FR-004**: 시스템은 관리자가 메시지 내용을 입력할 수 있어야 합니다. 내용은 필수 입력 항목입니다.

- **FR-005**: 시스템은 제목이나 내용 중 하나라도 비어있을 때 즉시 발송 버튼을 비활성화해야 합니다.

- **FR-006**: 시스템은 제목과 내용이 모두 입력되었을 때만 즉시 발송 버튼을 활성화해야 합니다.

- **FR-007**: 시스템은 메시지 유형이 선택되지 않았을 때 메시지 발송을 거부해야 합니다.

- **FR-008**: 시스템은 발송 대상이 선택되지 않았을 때 메시지 발송을 거부해야 합니다.

- **FR-009**: 시스템은 메시지 발송이 성공하면 발송 내역에 기록해야 합니다.

- **FR-010**: 시스템은 발송된 메시지의 정보(제목, 내용, 유형, 발송 대상, 발송 시간)를 저장해야 합니다.

### Key Entities *(include if feature involves data)*

- **알림 메시지**: 관리자가 유저에게 발송하는 알림 메시지를 나타냅니다. 속성으로는 제목, 내용, 메시지 유형(광고, 안내, 이벤트, 업데이트), 발송 대상(전체 회원, 활성 회원, 휴면 회원, VIP 회원), 발송 시간, 발송 상태가 포함됩니다.

- **메시지 유형**: 메시지의 분류를 나타냅니다. 가능한 값은 광고, 안내, 이벤트, 업데이트입니다.

- **발송 대상**: 메시지를 받을 유저 그룹을 나타냅니다. 가능한 값은 전체 회원, 활성 회원, 휴면 회원, VIP 회원입니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 메시지 유형과 발송 대상을 선택하고 제목과 내용을 입력한 후 3분 이내에 메시지를 발송할 수 있습니다.

- **SC-002**: 제목이나 내용이 비어있을 때 즉시 발송 버튼이 100%의 경우에 비활성화됩니다.

- **SC-003**: 제목과 내용이 모두 입력되었을 때 즉시 발송 버튼이 100%의 경우에 활성화됩니다.

- **SC-004**: 메시지 발송 시 필수 필드(유형, 대상, 제목, 내용)가 모두 입력되지 않은 경우 100%의 경우에 발송이 거부됩니다.

- **SC-005**: 메시지 발송이 성공하면 100%의 경우에 발송 내역에 기록됩니다.

- **SC-006**: 관리자는 메시지 발송 폼에서 모든 필수 정보를 입력하는 과정에서 오류 없이 완료할 수 있습니다.

## Assumptions

- 메시지 제목과 내용에 공백만 있는 경우는 비어있는 것으로 간주합니다.
- 메시지 발송은 실시간으로 처리되며, 발송 완료 후 즉시 발송 내역에 반영됩니다.
- 메시지 유형과 발송 대상은 기존 시스템에 정의된 값들을 사용합니다.
- 발송 대상에 선택된 회원 그룹에 실제 회원이 존재한다고 가정합니다.
- 메시지 발송은 네트워크 연결이 정상적인 환경에서 이루어진다고 가정합니다.
