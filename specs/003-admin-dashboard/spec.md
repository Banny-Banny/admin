# Feature Specification: 관리자 대시보드 조회 및 차트 시각화

**Feature Branch**: `003-admin-dashboard`  
**Created**: 2026-01-21  
**Status**: Draft  
**Input**: User description: "관리자 대시보드 - 대시보드 조회 및 차트 시각화 (1차)

**기능:**
관리자가 대시보드 접속 시 서비스 현황을 조회하고 차트로 시각화

**API 엔드포인트:**

1. GET /api/admin/dashboard/summary
   - 파라미터: 없음
   - 응답: 대시보드 요약 지표 (totalUsers, activeUsers, totalOrders, totalRevenue 등)

2. GET /api/admin/dashboard/charts
   - Query 파라미터:
     * period: 'day' | 'week' | 'month' (기본값: 'day')
     * startDate: string (선택)
     * endDate: string (선택)
   - 응답: 차트 데이터 (labels[], data[] 등)

3. GET /api/admin/dashboard/user-trends
   - Query 파라미터:
     * period: '90d' (기본값: '90d')
   - 응답: 최근 90일 가입/탈퇴 추이 (dates[], signups[], withdrawals[] 등)

**차트 시각화 요구사항:**
- Chart.js + react-chartjs-2 사용
- charts API: period 선택 옵션 제공 (일/주/월)
- user-trends API: Line Chart (가입/탈퇴 2개 라인)
- 반응형 디자인
- 툴팁, 레전드 포함

**작업 순서:**
1. API 타입 정의 (TypeScript)
   - Request 파라미터 타입 (query params)
   - Response 타입
2. Axios로 API 함수 작성 (3개)
3. React Query 훅 생성 (useQuery)
4. E2E 테스트 작성 및 통과 확인
5. Chart.js 및 react-chartjs-2 설치
6. 차트 컴포넌트 작성
7. UI에 데이터 바인딩

**중요: E2E 테스트가 통과된 후에만 UI 데이터 바인딩 작업 진행**

**기술 스택:**
- Axios (API 통신)
- React Query (서버 상태 관리)
- TypeScript
- Chart.js + react-chartjs-2 (차트 시각화)

**기존 상태:**
- UI 컴포넌트는 이미 존재
- 하드코딩된 더미 데이터 사용 중"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 대시보드 요약 지표 조회 (Priority: P1)

관리자가 대시보드에 접속하면 서비스의 핵심 요약 지표를 한눈에 확인할 수 있습니다. 이는 전체적인 서비스 현황을 즉시 파악하고 의사결정의 기초로 활용하기 위한 것입니다.

**Why this priority**: 관리자가 매일 첫 번째로 확인하는 핵심 정보로, 서비스 운영의 기본이 되는 기능입니다. 다른 기능들이 이 정보를 바탕으로 확장될 수 있습니다.

**Independent Test**: 관리자가 대시보드 페이지에 접속하면, 총 사용자 수, 활성 사용자 수, 총 주문 수, 총 매출 등의 핵심 지표가 즉시 표시됩니다. 이 정보만으로도 서비스 전체 현황을 파악할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인되어 있고, **When** 대시보드 페이지에 접속하면, **Then** 서비스 요약 지표(총 사용자, 활성 사용자, 총 주문 수, 총 매출 등)가 표시됩니다
2. **Given** 대시보드 페이지가 로드된 상태에서, **When** 데이터가 없는 경우, **Then** 적절한 빈 상태 메시지가 표시됩니다
3. **Given** 대시보드 페이지가 로드 중일 때, **When** 로딩 상태가 표시되면, **Then** 사용자는 데이터를 기다리고 있음을 인지할 수 있습니다

---

### User Story 2 - 기간별 차트 데이터 조회 및 시각화 (Priority: P2)

관리자가 일/주/월 단위로 서비스 데이터를 조회하고 차트로 시각화하여 시간에 따른 변화 추이를 분석할 수 있습니다.

**Why this priority**: 서비스 성장 추이와 트렌드를 파악하기 위한 핵심 분석 도구입니다. 요약 지표 다음으로 중요한 기능으로, 패턴 분석과 의사결정에 필요한 정보를 제공합니다.

**Independent Test**: 관리자가 기간 선택 옵션(일/주/월)을 선택하면, 해당 기간의 데이터가 차트로 표시됩니다. 이를 통해 시간에 따른 변화 추이를 시각적으로 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 대시보드 페이지에 접속한 관리자가, **When** 기간 선택 옵션(일/주/월)을 선택하면, **Then** 해당 기간의 데이터가 차트로 표시됩니다
2. **Given** 차트 데이터가 표시된 상태에서, **When** 사용자가 차트의 특정 지점에 마우스를 올리면, **Then** 해당 시점의 상세 정보가 툴팁으로 표시됩니다
3. **Given** 차트가 표시된 상태에서, **When** 시작일과 종료일을 직접 선택하면, **Then** 선택한 기간의 데이터가 차트에 반영됩니다
4. **Given** 다양한 화면 크기에서, **When** 차트를 조회하면, **Then** 차트가 화면 크기에 맞게 반응형으로 표시됩니다

---

### User Story 3 - 사용자 가입/탈퇴 추이 조회 및 시각화 (Priority: P2)

관리자가 최근 기간 동안의 사용자 가입 및 탈퇴 추이를 라인 차트로 조회하여 서비스의 사용자 동향을 분석할 수 있습니다.

**Why this priority**: 사용자 유지율과 이탈률을 파악하는 데 중요한 지표입니다. 사용자 성장 패턴을 이해하고 이탈 원인을 분석하는 데 도움이 됩니다.

**Independent Test**: 관리자가 사용자 추이 차트를 조회하면, 가입과 탈퇴 데이터가 두 개의 라인으로 표시되어 시간에 따른 변화를 비교할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 대시보드 페이지에 접속한 관리자가, **When** 사용자 추이 차트를 조회하면, **Then** 가입 및 탈퇴 데이터가 두 개의 라인으로 차트에 표시됩니다
2. **Given** 사용자 추이 차트가 표시된 상태에서, **When** 사용자가 특정 날짜에 마우스를 올리면, **Then** 해당 날짜의 가입 수와 탈퇴 수가 툴팁으로 표시됩니다
3. **Given** 사용자 추이 차트가 표시된 상태에서, **When** 차트 범례를 확인하면, **Then** 가입 라인과 탈퇴 라인이 구분되어 표시됩니다
4. **Given** 데이터가 없는 기간이 있을 때, **When** 차트를 조회하면, **Then** 해당 기간은 적절히 처리되어 표시됩니다

---

### Edge Cases

- 데이터가 전혀 없는 새로운 서비스의 경우 어떻게 표시되는가?
- API 응답이 지연되거나 실패하는 경우 어떻게 처리되는가?
- 매우 큰 기간 범위를 선택한 경우 성능이 어떻게 유지되는가?
- 여러 관리자가 동시에 대시보드를 조회할 때 데이터 일관성이 어떻게 보장되는가?
- 차트 데이터에 음수 값이나 비정상적인 값이 포함된 경우 어떻게 표시되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자가 대시보드에 접속할 때 서비스 요약 지표(총 사용자, 활성 사용자, 총 주문 수, 총 매출)를 표시해야 합니다
- **FR-002**: 시스템은 관리자가 일/주/월 단위로 기간을 선택하여 차트 데이터를 조회할 수 있도록 해야 합니다
- **FR-003**: 시스템은 관리자가 시작일과 종료일을 직접 지정하여 특정 기간의 차트 데이터를 조회할 수 있도록 해야 합니다
- **FR-004**: 시스템은 선택한 기간의 차트 데이터를 시각적으로 표시해야 합니다
- **FR-005**: 시스템은 관리자가 최근 90일 동안의 사용자 가입 및 탈퇴 추이를 조회할 수 있도록 해야 합니다
- **FR-006**: 시스템은 사용자 가입과 탈퇴 데이터를 구분하여 라인 차트로 표시해야 합니다
- **FR-007**: 시스템은 차트에 마우스를 올렸을 때 해당 시점의 상세 정보를 툴팁으로 표시해야 합니다
- **FR-008**: 시스템은 차트에 범례를 표시하여 데이터 구분을 명확히 해야 합니다
- **FR-009**: 시스템은 다양한 화면 크기에서 차트가 적절히 표시되도록 반응형 디자인을 제공해야 합니다
- **FR-010**: 시스템은 데이터 로딩 중 로딩 상태를 표시해야 합니다
- **FR-011**: 시스템은 데이터가 없을 때 적절한 빈 상태 메시지를 표시해야 합니다
- **FR-012**: 시스템은 데이터 조회 실패 시 사용자에게 적절한 오류 메시지를 표시해야 합니다

### Key Entities

- **대시보드 요약 지표**: 서비스의 핵심 지표 집합 (총 사용자 수, 활성 사용자 수, 총 주문 수, 총 매출 등)
- **차트 데이터**: 특정 기간 동안의 서비스 지표 데이터 (시간별/일별/주별/월별 데이터 포인트, 레이블 정보)
- **사용자 추이 데이터**: 특정 기간 동안의 사용자 가입 및 탈퇴 데이터 (날짜별 가입 수, 날짜별 탈퇴 수)
- **기간 필터**: 데이터 조회에 사용되는 시간 범위 설정 (기간 타입, 시작일, 종료일)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 대시보드에 접속하여 핵심 요약 지표를 확인하는 데 3초 이내가 소요됩니다
- **SC-002**: 관리자가 기간을 선택하여 차트 데이터를 조회하는 데 5초 이내가 소요됩니다
- **SC-003**: 차트 데이터 조회 시 데이터 포인트가 정확하게 표시되며, 오류율이 1% 미만입니다
- **SC-004**: 다양한 화면 크기(데스크톱, 태블릿, 모바일)에서 차트가 올바르게 표시되며, 레이아웃이 깨지지 않습니다
- **SC-005**: 데이터 로딩 중 및 오류 발생 시 사용자가 적절한 피드백을 받으며, 사용성 저하 없이 오류에서 복구할 수 있습니다
- **SC-006**: 동시에 10명 이상의 관리자가 대시보드를 조회해도 성능 저하 없이 정상적으로 작동합니다
