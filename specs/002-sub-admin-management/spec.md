# Feature Specification: 하위 관리자 계정 생성 및 관리

**Feature Branch**: `002-sub-admin-management`  
**Created**: 2025-01-19  
**Status**: Draft  
**Input**: User description: "슈퍼 어드민(최고 관리자)이 @index.tsx (192-198)이 버튼을 눌러서 하위 관리자들을 추가할 수 있어. 즉 관리자 계정을 생성할 수 있고, 관리자들은 여기서 만든 계정으로 로그인해서 관리자 권한을 얻고 이 관리자 페이지에 들어올 수 있는거야. 추가함과 동시에 관리자 목록에도 추가되고 알림/마케팅 글도 각자 아이디로 작성하고 관리할 수 있어야해."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 슈퍼 어드민이 하위 관리자 계정 생성 (Priority: P1)

슈퍼 어드민이 관리자 추가 버튼을 클릭하여 하위 관리자 계정을 생성할 수 있어야 합니다. 계정 생성 시 이름, 이메일, 권한, 임시 비밀번호를 입력하고, 생성된 계정은 즉시 관리자 목록에 표시되며, 생성된 관리자는 해당 계정으로 로그인하여 관리자 권한을 획득할 수 있어야 합니다.

**Why this priority**: 하위 관리자 계정 생성은 이 기능의 핵심이며, 다른 모든 기능의 전제 조건입니다. 이 기능 없이는 하위 관리자를 추가할 수 없습니다.

**Independent Test**: 슈퍼 어드민이 관리자 추가 버튼을 클릭하고 필수 정보를 입력하여 하위 관리자 계정을 생성하고, 생성된 계정이 관리자 목록에 표시되는 것을 테스트할 수 있습니다. 이 기능만으로도 슈퍼 어드민이 하위 관리자를 추가할 수 있는 최소한의 가치를 제공합니다.

**Acceptance Scenarios**:

1. **Given** 슈퍼 어드민이 로그인한 상태에서 사용자 관리 페이지에 접속한 상태, **When** "관리자 추가하기" 버튼을 클릭하면, **Then** 관리자 추가 폼이 표시됩니다.
2. **Given** 관리자 추가 폼이 표시된 상태, **When** 이름, 이메일, 권한, 임시 비밀번호를 입력하고 "관리자 추가" 버튼을 클릭하면, **Then** 하위 관리자 계정이 생성되고 관리자 목록에 즉시 추가되며 성공 메시지가 표시됩니다.
3. **Given** 관리자 추가 폼이 표시된 상태, **When** 필수 필드(이름, 이메일, 비밀번호)를 비워두고 "관리자 추가" 버튼을 클릭하면, **Then** 입력 필드 검증 오류 메시지가 표시됩니다.
4. **Given** 관리자 추가 폼이 표시된 상태, **When** 이미 존재하는 이메일 주소를 입력하고 "관리자 추가" 버튼을 클릭하면, **Then** 중복 이메일 오류 메시지가 표시되고 계정이 생성되지 않습니다.
5. **Given** 관리자 추가 폼이 표시된 상태, **When** 유효하지 않은 이메일 형식을 입력하고 "관리자 추가" 버튼을 클릭하면, **Then** 이메일 형식 오류 메시지가 표시됩니다.
6. **Given** 관리자 추가 폼이 표시된 상태, **When** 최소 길이 미만의 비밀번호를 입력하고 "관리자 추가" 버튼을 클릭하면, **Then** 비밀번호 길이 오류 메시지가 표시됩니다.

### User Story 2 - 생성된 관리자가 로그인하여 관리자 권한 획득 (Priority: P1)

생성된 하위 관리자가 이메일과 임시 비밀번호로 로그인하여 관리자 권한을 획득하고 관리자 페이지에 접근할 수 있어야 합니다.

**Why this priority**: 생성된 계정으로 로그인할 수 있어야 하위 관리자가 시스템을 사용할 수 있습니다. 이 기능 없이는 계정 생성만으로는 실제 사용이 불가능합니다.

**Independent Test**: 생성된 하위 관리자 계정의 이메일과 비밀번호로 로그인 페이지에서 로그인을 시도하고, 로그인 성공 후 관리자 대시보드에 접근할 수 있는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 하위 관리자 계정이 생성된 상태, **When** 생성된 이메일과 임시 비밀번호로 로그인 페이지에서 로그인을 시도하면, **Then** 로그인이 성공하고 관리자 대시보드로 이동하며 관리자 권한을 획득합니다.
2. **Given** 하위 관리자 계정이 생성된 상태, **When** 잘못된 비밀번호로 로그인을 시도하면, **Then** 로그인 실패 메시지가 표시되고 로그인 페이지에 머물러 있습니다.
3. **Given** 하위 관리자가 로그인에 성공한 상태, **When** 관리자 페이지의 다른 기능에 접근하면, **Then** 해당 관리자의 권한에 따라 접근이 허용되거나 제한됩니다.

---

### User Story 3 - 관리자 목록에 자동 추가 및 표시 (Priority: P2)

하위 관리자 계정이 생성되면 즉시 관리자 목록에 추가되어 표시되어야 합니다. 관리자 목록에는 이름, 이메일, 권한, 가입일, 마지막 접속 정보가 표시되어야 합니다.

**Why this priority**: 관리자 목록에 표시되어야 슈퍼 어드민이 생성된 관리자를 확인하고 관리할 수 있습니다. 하지만 계정 생성 기능이 먼저 구현되어야 하므로 P2로 설정합니다.

**Independent Test**: 하위 관리자 계정을 생성한 후 관리자 목록 섹션에서 새로 생성된 관리자가 표시되는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 하위 관리자 계정이 생성된 상태, **When** 관리자 목록 섹션을 확인하면, **Then** 새로 생성된 관리자가 목록에 표시되며 이름, 이메일, 권한, 가입일 정보가 정확하게 표시됩니다.
2. **Given** 여러 하위 관리자가 생성된 상태, **When** 관리자 목록을 확인하면, **Then** 모든 관리자가 목록에 표시되며 최신 생성 순서로 정렬되어 표시됩니다.
3. **Given** 하위 관리자가 로그인한 상태, **When** 관리자 목록을 확인하면, **Then** 해당 관리자의 마지막 접속 시간이 업데이트되어 표시됩니다.

---

### User Story 4 - 각 관리자가 알림/마케팅 글 작성 및 관리 (Priority: P2)

각 관리자는 자신의 계정으로 알림/마케팅 글을 작성하고 관리할 수 있어야 합니다. 작성된 글에는 작성자 정보(관리자 이름 또는 이메일)가 표시되어야 하며, 각 관리자는 자신이 작성한 글만 수정하거나 삭제할 수 있어야 합니다.

**Why this priority**: 관리자별로 콘텐츠를 관리할 수 있어야 책임 소재가 명확해지고 협업이 가능합니다. 하지만 계정 생성 및 로그인 기능이 먼저 구현되어야 하므로 P2로 설정합니다.

**Independent Test**: 하위 관리자로 로그인한 후 알림/마케팅 페이지에서 글을 작성하고, 작성된 글에 작성자 정보가 표시되는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 하위 관리자가 로그인한 상태에서 알림/마케팅 페이지에 접속한 상태, **When** 메시지를 작성하고 발송하면, **Then** 메시지가 발송되며 작성자 정보(관리자 이름 또는 이메일)가 발송 내역에 표시됩니다.
2. **Given** 하위 관리자가 작성한 메시지가 발송 내역에 있는 상태, **When** 해당 메시지를 확인하면, **Then** 작성자 정보가 정확하게 표시됩니다.
3. **Given** 여러 관리자가 각각 메시지를 작성한 상태, **When** 발송 내역을 확인하면, **Then** 각 메시지에 작성자 정보가 표시되어 누가 작성했는지 구분할 수 있습니다.
4. **Given** 하위 관리자가 작성한 메시지가 있는 상태, **When** 해당 관리자가 메시지를 수정하거나 삭제하려고 시도하면, **Then** 자신이 작성한 메시지만 수정하거나 삭제할 수 있습니다.
5. **Given** 다른 관리자가 작성한 메시지가 있는 상태, **When** 하위 관리자가 해당 메시지를 수정하거나 삭제하려고 시도하면, **Then** 권한 오류 메시지가 표시되고 수정 또는 삭제가 불가능합니다.

---

### Edge Cases

- 슈퍼 어드민이 아닌 일반 관리자가 관리자 추가 버튼을 클릭하면 어떻게 처리할까요?
- 동일한 이메일로 여러 번 계정 생성을 시도하면 어떻게 처리할까요?
- 생성된 관리자 계정을 삭제할 수 있어야 할까요? 삭제 시 작성한 알림/마케팅 글은 어떻게 처리할까요?
- 관리자 계정 생성 중 네트워크 오류가 발생하면 어떻게 처리할까요?
- 관리자 목록이 많아질 경우 페이지네이션이 필요한가요?
- 슈퍼 어드민이 자신의 계정을 삭제할 수 있어야 할까요?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 슈퍼 어드민만 하위 관리자 계정을 생성할 수 있어야 합니다.
- **FR-002**: 시스템은 관리자 추가 폼에서 이름, 이메일, 권한, 임시 비밀번호를 입력받아야 합니다.
- **FR-003**: 시스템은 관리자 계정 생성 시 이메일 중복을 검사해야 합니다.
- **FR-004**: 시스템은 관리자 계정 생성 시 이메일 형식을 검증해야 합니다.
- **FR-005**: 시스템은 관리자 계정 생성 시 비밀번호 최소 길이를 검증해야 합니다.
- **FR-006**: 시스템은 관리자 계정 생성 성공 시 즉시 관리자 목록에 추가해야 합니다.
- **FR-007**: 시스템은 생성된 관리자 계정으로 로그인할 수 있어야 합니다.
- **FR-008**: 시스템은 관리자 목록에 이름, 이메일, 권한, 가입일, 마지막 접속 정보를 표시해야 합니다.
- **FR-009**: 시스템은 각 관리자가 알림/마케팅 글을 작성할 수 있어야 합니다.
- **FR-010**: 시스템은 작성된 알림/마케팅 글에 작성자 정보(관리자 이름 또는 이메일)를 표시해야 합니다.
- **FR-011**: 시스템은 각 관리자가 자신이 작성한 알림/마케팅 글만 수정하거나 삭제할 수 있어야 합니다.
- **FR-012**: 시스템은 관리자 계정 생성 실패 시 명확한 오류 메시지를 표시해야 합니다.
- **FR-013**: 시스템은 관리자 목록에서 최신 생성 순서로 관리자를 표시해야 합니다.
- **FR-014**: 시스템은 관리자 로그인 시 마지막 접속 시간을 업데이트해야 합니다.

### Key Entities

- **하위 관리자 계정**: 슈퍼 어드민에 의해 생성되는 관리자 계정. 이름, 이메일, 권한, 비밀번호 등의 속성을 가집니다. 생성된 계정으로 로그인하여 관리자 권한을 획득할 수 있습니다.
- **관리자 목록**: 시스템에 등록된 모든 관리자 계정의 목록. 각 관리자의 이름, 이메일, 권한, 가입일, 마지막 접속 정보를 포함합니다.
- **알림/마케팅 메시지**: 관리자가 작성하는 알림 또는 마케팅 메시지. 제목, 내용, 유형, 발송 대상, 발송 시간 등의 속성을 가지며, 작성자 정보(관리자 이름 또는 이메일)를 포함합니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 슈퍼 어드민은 관리자 추가 폼을 열고 필수 정보를 입력하여 30초 이내에 하위 관리자 계정을 생성할 수 있습니다.
- **SC-002**: 관리자 계정 생성 시도 중 95% 이상이 3초 이내에 응답을 받습니다.
- **SC-003**: 유효한 정보로 관리자 계정 생성 시도 시 99% 이상이 성공적으로 계정이 생성됩니다.
- **SC-004**: 중복 이메일 또는 유효하지 않은 정보로 계정 생성 시도 시 100% 적절한 오류 메시지가 표시됩니다.
- **SC-005**: 생성된 관리자 계정으로 로그인 시도 시 99% 이상이 성공적으로 로그인됩니다.
- **SC-006**: 관리자 계정 생성 성공 시 100% 즉시 관리자 목록에 추가되어 표시됩니다.
- **SC-007**: 관리자가 알림/마케팅 글을 작성할 때 100% 작성자 정보가 저장되고 표시됩니다.
- **SC-008**: 관리자가 자신이 작성한 글을 수정하거나 삭제할 때 100% 권한 검증이 수행됩니다.

## Assumptions

- 슈퍼 어드민은 이미 로그인되어 있고 관리자 페이지에 접근할 수 있습니다.
- 관리자 로그인 기능은 이미 구현되어 있으며 (001-admin-auth), 생성된 하위 관리자 계정도 동일한 로그인 API를 사용합니다.
- 관리자 역할은 SUPER_ADMIN, ADMIN 등으로 구분되며, 슈퍼 어드민만 하위 관리자를 생성할 수 있습니다.
- 비밀번호는 최소 8자 이상이어야 합니다.
- 이메일은 유효한 형식이어야 하며, 시스템 내에서 고유해야 합니다.
- 관리자 목록은 실시간으로 업데이트됩니다.
- 알림/마케팅 메시지 작성 기능은 이미 존재하며 (MarketingPage), 작성자 정보를 추가하는 기능이 필요합니다.
- 각 관리자는 자신이 작성한 메시지만 수정하거나 삭제할 수 있으며, 슈퍼 어드민은 모든 메시지를 관리할 수 있습니다.

## Dependencies

- 백엔드에서 제공하는 관리자 계정 생성 API:
  - 관리자 계정 생성 API (이름, 이메일, 권한, 비밀번호를 입력받아 계정 생성)
  - 관리자 목록 조회 API
  - 관리자 계정 삭제 API (선택적)
- 기존 관리자 로그인 기능 (001-admin-auth):
  - 관리자 로그인 API
  - 인증 세션 관리
- 기존 알림/마케팅 기능:
  - 메시지 작성 및 발송 기능
  - 발송 내역 조회 기능
- 슈퍼 어드민 권한 검증 기능
- 사용자 관리 페이지 (UsersPage)의 관리자 추가 폼 UI
