## User Scenarios & Testing *(mandatory)*

### User Story 1 - 대시보드 조회 및 문의 관리 (Priority: P1)

관리자가 로그인 후 대시보드에서 전체 통계를 확인하고, 최근 고객 문의 사항을 조회하며, 문의를 선택하여 채팅 인터페이스를 통해 고객과 소통할 수 있어야 합니다.

**Why this priority**: 대시보드는 관리자가 시스템에 접속했을 때 가장 먼저 보는 화면이며, 고객 문의 관리는 관리자의 핵심 업무입니다. 이 기능 없이는 관리자가 시스템의 전반적인 상태를 파악하거나 고객 지원을 제공할 수 없습니다.

**Independent Test**: 관리자가 로그인 후 대시보드에 접속하여 최근 문의 목록을 확인하고, 특정 문의를 선택하여 채팅 인터페이스에서 메시지를 주고받는 것을 테스트할 수 있습니다. 이 기능만으로도 관리자가 고객 지원의 핵심 업무를 수행할 수 있는 최소한의 가치를 제공합니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인한 상태, **When** 대시보드 페이지에 접속하면, **Then** 최근 문의 사항 목록이 표시되고 각 문의의 상태(대기중, 처리중, 완료), 우선순위(긴급, 보통, 낮음), 고객 정보가 표시됩니다.
2. **Given** 관리자가 대시보드에서 문의 목록을 확인한 상태, **When** 검색어를 입력하거나 상태/우선순위 필터를 적용하면, **Then** 해당 조건에 맞는 문의만 필터링되어 표시됩니다.
3. **Given** 관리자가 문의 목록을 확인한 상태, **When** 특정 문의를 클릭하면, **Then** 채팅 인터페이스가 열리고 해당 고객과의 대화 내역이 표시되며, 관리자가 메시지를 입력하여 응답할 수 있습니다.
4. **Given** 관리자가 채팅 인터페이스에서 고객에게 응답한 상태, **When** 메시지를 전송하면, **Then** 메시지가 대화 내역에 추가되고 고객에게 전달됩니다.
5. **Given** 관리자가 문의 목록을 확인한 상태, **When** 페이지네이션을 사용하여 다음 페이지로 이동하면, **Then** 다음 페이지의 문의 목록이 표시됩니다.

### User Story 2 - 사용자 관리 (Priority: P1)

관리자가 일반 사용자와 관리자 계정을 조회, 검색, 필터링하고, 사용자 상태를 변경하거나 새로운 관리자를 추가할 수 있어야 합니다.

**Why this priority**: 사용자 관리는 관리자 시스템의 핵심 기능 중 하나입니다. 관리자는 사용자 정보를 확인하고, 사용자 상태를 관리하며, 필요시 새로운 관리자를 추가할 수 있어야 합니다.

**Independent Test**: 관리자가 사용자 관리 페이지에 접속하여 사용자 목록을 조회하고, 검색/필터링 기능을 사용하며, 사용자 상태를 변경하거나 새로운 관리자를 추가하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 사용자 관리 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** 일반 사용자 목록과 관리자 목록이 각각 표시되며, 사용자 정보(이름, 닉네임, 이메일, 플랫폼, 상태, 가입일, 마지막 접속)가 표시됩니다.
2. **Given** 관리자가 사용자 목록을 확인한 상태, **When** 검색어를 입력하거나 상태/플랫폼 필터를 적용하면, **Then** 해당 조건에 맞는 사용자만 필터링되어 표시됩니다.
3. **Given** 관리자가 사용자 목록에서 특정 사용자를 확인한 상태, **When** 사용자의 상태 변경 메뉴를 통해 상태를 변경하면, **Then** 사용자의 상태가 업데이트되고 목록에 반영됩니다.
4. **Given** 관리자가 관리자 추가 버튼을 클릭한 상태, **When** 관리자 정보(이름, 이메일, 권한, 임시 비밀번호)를 입력하고 제출하면, **Then** 새로운 관리자 계정이 생성되고 관리자 목록에 추가됩니다.
5. **Given** 관리자가 관리자 목록을 확인한 상태, **When** 최고관리자가 아닌 관리자의 삭제 버튼을 클릭하면, **Then** 확인 후 해당 관리자가 목록에서 제거됩니다.

### User Story 3 - 상품 관리 (Priority: P2)

관리자가 상품을 등록, 조회, 수정할 수 있어야 합니다.

**Why this priority**: 상품 관리는 전자상거래 시스템의 핵심 기능입니다. 관리자는 상품 정보를 관리하고 재고를 추적할 수 있어야 합니다.

**Independent Test**: 관리자가 상품 관리 페이지에 접속하여 상품 목록을 확인하고, 새로운 상품을 등록하거나 기존 상품 정보를 수정하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 상품 관리 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** 등록된 상품 목록이 표시되며 각 상품의 정보(이름, 카테고리, 가격, 할인가, 재고, 상태)가 표시됩니다.
2. **Given** 관리자가 상품 등록 버튼을 클릭한 상태, **When** 상품 정보(이름, 카테고리, 가격, 할인가, 재고, 상태, 설명, 태그)를 입력하고 제출하면, **Then** 새로운 상품이 등록되고 목록에 추가됩니다.
3. **Given** 관리자가 상품 목록을 확인한 상태, **When** 상품의 상태가 변경되면, **Then** 상품 목록에 변경된 상태가 반영됩니다.

---

### User Story 4 - 분석 및 통계 조회 (Priority: P2)

관리자가 시스템의 통계 데이터를 조회하고 분석할 수 있어야 합니다.

**Why this priority**: 분석 기능은 관리자가 비즈니스 성과를 파악하고 의사결정을 내리는 데 도움이 됩니다.

**Independent Test**: 관리자가 분석 페이지에 접속하여 통계 데이터(방문자, 전환율, 매출, 카테고리별 비중 등)를 확인하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 분석 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** 주요 지표(평균 방문 시간, 이탈률, 페이지뷰)가 표시되고, 월별 성과 차트와 카테고리별 매출 비중 차트가 표시됩니다.
2. **Given** 관리자가 분석 페이지를 확인한 상태, **When** 차트 데이터를 확인하면, **Then** 시각적으로 이해하기 쉬운 형태로 데이터가 표시됩니다.

---

### User Story 5 - 공지사항 관리 (Priority: P2)

관리자가 공지사항을 작성, 조회, 수정, 삭제할 수 있어야 합니다.

**Why this priority**: 공지사항 관리는 사용자에게 중요한 정보를 전달하는 수단입니다.

**Independent Test**: 관리자가 공지사항 페이지에 접속하여 공지사항 목록을 확인하고, 새로운 공지사항을 작성하거나 기존 공지사항을 수정/삭제하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 공지사항 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** 공지사항 목록이 표시되며 각 공지사항의 제목, 내용, 작성자, 작성일, 조회수가 표시됩니다.
2. **Given** 관리자가 공지사항 작성 버튼을 클릭한 상태, **When** 공지사항 정보(제목, 내용, 상단 고정 여부)를 입력하고 제출하면, **Then** 새로운 공지사항이 등록되고 목록에 추가됩니다.
3. **Given** 관리자가 공지사항 목록에서 특정 공지사항을 클릭한 상태, **When** 상세 페이지가 표시되면, **Then** 공지사항의 전체 내용과 메타 정보가 표시되며, 삭제 버튼을 통해 공지사항을 삭제할 수 있습니다.
4. **Given** 관리자가 공지사항 목록을 확인한 상태, **When** 검색어를 입력하면, **Then** 해당 검색어가 포함된 공지사항만 필터링되어 표시됩니다.
5. **Given** 관리자가 공지사항 목록을 확인한 상태, **When** 상단 고정된 공지사항이 있으면, **Then** 해당 공지사항이 목록 상단에 표시됩니다.

### User Story 6 - 마케팅 메시지 발송 (Priority: P3)

관리자가 사용자에게 마케팅 메시지를 발송하고 발송 내역을 관리할 수 있어야 합니다.

**Why this priority**: 마케팅 메시지 발송은 사용자와의 소통을 강화하고 비즈니스 성과를 향상시키는 데 도움이 됩니다.

**Independent Test**: 관리자가 마케팅 페이지에 접속하여 메시지를 작성하고 발송하며, 발송 내역을 확인하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 마케팅 페이지에 접속한 상태, **When** 메시지 발송 탭을 선택하면, **Then** 메시지 작성 폼이 표시되며 메시지 유형, 발송 대상, 제목, 내용, 발송 시간을 설정할 수 있습니다.
2. **Given** 관리자가 메시지 작성 폼을 작성한 상태, **When** 즉시 발송 또는 예약 발송을 선택하고 제출하면, **Then** 메시지가 발송되거나 예약되며 발송 내역에 추가됩니다.
3. **Given** 관리자가 발송 내역 탭을 선택한 상태, **When** 페이지가 로드되면, **Then** 발송된 메시지 목록이 표시되며 각 메시지의 유형, 발송 대상, 수신자 수, 오픈률, 상태, 발송일시가 표시됩니다.
4. **Given** 관리자가 발송 내역을 확인한 상태, **When** 검색어를 입력하거나 유형 필터를 적용하면, **Then** 해당 조건에 맞는 메시지만 필터링되어 표시됩니다.

### User Story 7 - 시스템 설정 관리 (Priority: P3)

관리자가 시스템 설정을 변경할 수 있어야 합니다.

**Why this priority**: 시스템 설정 관리는 관리자가 시스템을 자신의 필요에 맞게 조정할 수 있게 합니다.

**Independent Test**: 관리자가 설정 페이지에 접속하여 알림 설정, 보안 설정, 지역 및 언어 설정, 외관 설정을 변경하는 것을 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 설정 페이지에 접속한 상태, **When** 페이지가 로드되면, **Then** 알림 설정, 보안 설정, 지역 및 언어 설정, 외관 설정 섹션이 표시됩니다.
2. **Given** 관리자가 알림 설정을 확인한 상태, **When** 이메일 알림 또는 푸시 알림을 활성화/비활성화하면, **Then** 설정이 저장되고 적용됩니다.
3. **Given** 관리자가 보안 설정을 확인한 상태, **When** 현재 비밀번호와 새 비밀번호를 입력하고 저장하면, **Then** 비밀번호가 변경됩니다.
4. **Given** 관리자가 지역 및 언어 설정을 확인한 상태, **When** 언어 또는 시간대를 변경하고 저장하면, **Then** 설정이 저장되고 적용됩니다.
5. **Given** 관리자가 외관 설정을 확인한 상태, **When** 테마(라이트, 다크, 자동)를 선택하고 저장하면, **Then** 테마가 변경되고 적용됩니다.

---

### Edge Cases

- 대시보드에 문의가 없을 때 어떻게 표시할까요?
- 사용자 검색 결과가 없을 때 어떻게 표시할까요?
- 상품 등록 시 필수 필드가 누락되었을 때 어떻게 처리할까요?
- 공지사항 작성 중 브라우저를 닫으면 어떻게 처리할까요?
- 마케팅 메시지 발송 중 네트워크 오류가 발생하면 어떻게 처리할까요?
- 설정 변경 중 다른 관리자가 동시에 변경하면 어떻게 처리할까요?
- 페이지네이션에서 마지막 페이지를 넘어가면 어떻게 처리할까요?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자가 대시보드에서 최근 문의 사항 목록을 조회할 수 있어야 합니다.
- **FR-002**: 시스템은 관리자가 문의 목록을 검색, 필터링(상태, 우선순위)할 수 있어야 합니다.
- **FR-003**: 시스템은 관리자가 문의를 선택하여 채팅 인터페이스를 통해 고객과 소통할 수 있어야 합니다.
- **FR-004**: 시스템은 관리자가 채팅 인터페이스에서 메시지를 입력하고 전송할 수 있어야 합니다.
- **FR-005**: 시스템은 관리자가 일반 사용자 목록을 조회할 수 있어야 합니다.
- **FR-006**: 시스템은 관리자가 사용자 목록을 검색, 필터링(상태, 플랫폼)할 수 있어야 합니다.
- **FR-007**: 시스템은 관리자가 사용자 상태를 변경할 수 있어야 합니다.
- **FR-008**: 시스템은 관리자가 관리자 목록을 조회할 수 있어야 합니다.
- **FR-009**: 시스템은 관리자가 새로운 관리자 계정을 추가할 수 있어야 합니다.
- **FR-010**: 시스템은 관리자가 관리자 계정을 삭제할 수 있어야 합니다 (최고관리자 제외).
- **FR-011**: 시스템은 관리자가 상품 목록을 조회할 수 있어야 합니다.
- **FR-012**: 시스템은 관리자가 새로운 상품을 등록할 수 있어야 합니다.
- **FR-013**: 시스템은 관리자가 상품 정보(이름, 카테고리, 가격, 할인가, 재고, 상태, 설명, 태그)를 입력할 수 있어야 합니다.
- **FR-014**: 시스템은 관리자가 분석 페이지에서 통계 데이터를 조회할 수 있어야 합니다.
- **FR-015**: 시스템은 관리자가 공지사항 목록을 조회할 수 있어야 합니다.
- **FR-016**: 시스템은 관리자가 새로운 공지사항을 작성할 수 있어야 합니다.
- **FR-017**: 시스템은 관리자가 공지사항을 상단 고정할 수 있어야 합니다.
- **FR-018**: 시스템은 관리자가 공지사항을 삭제할 수 있어야 합니다.
- **FR-019**: 시스템은 관리자가 공지사항 목록을 검색할 수 있어야 합니다.
- **FR-020**: 시스템은 관리자가 마케팅 메시지를 작성하고 발송할 수 있어야 합니다.
- **FR-021**: 시스템은 관리자가 마케팅 메시지를 즉시 발송하거나 예약 발송할 수 있어야 합니다.
- **FR-022**: 시스템은 관리자가 발송 내역을 조회할 수 있어야 합니다.
- **FR-023**: 시스템은 관리자가 발송 내역을 검색, 필터링(유형)할 수 있어야 합니다.
- **FR-024**: 시스템은 관리자가 시스템 설정을 변경할 수 있어야 합니다.
- **FR-025**: 시스템은 관리자가 알림 설정을 변경할 수 있어야 합니다.
- **FR-026**: 시스템은 관리자가 보안 설정(비밀번호 변경)을 변경할 수 있어야 합니다.
- **FR-027**: 시스템은 관리자가 지역 및 언어 설정을 변경할 수 있어야 합니다.
- **FR-028**: 시스템은 관리자가 외관 설정(테마)을 변경할 수 있어야 합니다.
- **FR-029**: 시스템은 관리자가 사이드바를 통해 각 페이지로 이동할 수 있어야 합니다.
- **FR-030**: 시스템은 관리자가 헤더에서 로그아웃할 수 있어야 합니다.
- **FR-031**: 시스템은 관리자가 페이지네이션을 통해 목록을 탐색할 수 있어야 합니다.
- **FR-032**: 시스템은 관리자가 인증되지 않은 상태에서 보호된 페이지에 접근하려고 하면 로그인 페이지로 리다이렉트해야 합니다.

### Key Entities

- **문의**: 고객이 관리자에게 보낸 문의 사항. 고객 정보, 제목, 내용, 상태, 우선순위, 시간 정보를 포함합니다.
- **메시지**: 채팅 인터페이스에서 주고받는 메시지. 발신자(관리자/고객), 내용, 시간 정보를 포함합니다.
- **사용자**: 시스템을 사용하는 일반 사용자. 이름, 닉네임, 이메일, 플랫폼, 상태, 가입일, 마지막 접속 정보를 포함합니다.
- **관리자**: 시스템을 관리하는 관리자 계정. 이름, 이메일, 권한, 가입일, 마지막 접속 정보를 포함합니다.
- **상품**: 판매되는 상품. 이름, 카테고리, 가격, 할인가, 재고, 상태, 설명, 태그, 이미지, 생성일 정보를 포함합니다.
- **공지사항**: 사용자에게 전달하는 공지사항. 제목, 내용, 작성자, 작성일, 조회수, 상단 고정 여부를 포함합니다.
- **마케팅 메시지**: 사용자에게 발송하는 마케팅 메시지. 유형, 발송 대상, 제목, 내용, 발송 시간, 수신자 수, 오픈률, 상태를 포함합니다.
- **통계 데이터**: 시스템의 통계 정보. 방문자 수, 전환율, 매출, 카테고리별 비중, 페이지뷰 등의 정보를 포함합니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 대시보드 페이지에 접속하여 3초 이내에 최근 문의 목록을 확인할 수 있습니다.
- **SC-002**: 관리자는 문의 목록에서 검색어를 입력하여 1초 이내에 필터링된 결과를 확인할 수 있습니다.
- **SC-003**: 관리자는 채팅 인터페이스에서 메시지를 입력하고 2초 이내에 전송할 수 있습니다.
- **SC-004**: 관리자는 사용자 관리 페이지에 접속하여 3초 이내에 사용자 목록을 확인할 수 있습니다.
- **SC-005**: 관리자는 사용자 상태를 변경하고 2초 이내에 변경 사항이 반영되는 것을 확인할 수 있습니다.
- **SC-006**: 관리자는 새로운 관리자를 추가하고 5초 이내에 관리자 목록에 추가되는 것을 확인할 수 있습니다.
- **SC-007**: 관리자는 상품 관리 페이지에 접속하여 3초 이내에 상품 목록을 확인할 수 있습니다.
- **SC-008**: 관리자는 새로운 상품을 등록하고 5초 이내에 상품 목록에 추가되는 것을 확인할 수 있습니다.
- **SC-009**: 관리자는 분석 페이지에 접속하여 3초 이내에 통계 데이터를 확인할 수 있습니다.
- **SC-010**: 관리자는 공지사항 페이지에 접속하여 3초 이내에 공지사항 목록을 확인할 수 있습니다.
- **SC-011**: 관리자는 새로운 공지사항을 작성하고 5초 이내에 공지사항 목록에 추가되는 것을 확인할 수 있습니다.
- **SC-012**: 관리자는 마케팅 메시지를 작성하고 5초 이내에 발송하거나 예약할 수 있습니다.
- **SC-013**: 관리자는 발송 내역을 조회하여 3초 이내에 발송된 메시지 목록을 확인할 수 있습니다.
- **SC-014**: 관리자는 설정 페이지에서 설정을 변경하고 3초 이내에 변경 사항이 저장되는 것을 확인할 수 있습니다.
- **SC-015**: 관리자는 사이드바를 통해 각 페이지로 이동하고 2초 이내에 해당 페이지가 로드됩니다.
- **SC-016**: 시스템은 인증되지 않은 사용자가 보호된 페이지에 접근하려고 할 때 1초 이내에 로그인 페이지로 리다이렉트합니다.
- **SC-017**: 페이지네이션을 사용하여 목록을 탐색할 때 2초 이내에 다음 페이지가 로드됩니다.
- **SC-018**: 검색 및 필터링 기능 사용 시 95% 이상의 경우 1초 이내에 결과가 표시됩니다.

## Assumptions

- 관리자는 이미 인증 시스템(001-admin-auth)을 통해 로그인한 상태입니다.
- 백엔드 API가 각 기능에 대한 엔드포인트를 제공합니다.
- 사용자 데이터, 상품 데이터, 문의 데이터 등은 백엔드에서 관리됩니다.
- 관리자는 적절한 권한을 가지고 있습니다.
- 시스템은 반응형 디자인을 지원합니다.
- 브라우저는 최신 버전이며 JavaScript가 활성화되어 있습니다.
- 네트워크 연결이 안정적입니다.

## Dependencies

- 관리자 인증 시스템 (001-admin-auth): 관리자가 로그인하고 인증 상태를 유지하는 기능
- 백엔드 API: 각 기능에 대한 REST API 엔드포인트
  - 문의 조회 API
  - 사용자 조회/수정 API
  - 관리자 생성/삭제 API
  - 상품 조회/등록 API
  - 통계 데이터 조회 API
  - 공지사항 조회/작성/삭제 API
  - 마케팅 메시지 발송 API
  - 설정 변경 API
- UI 컴포넌트 라이브러리: Radix UI 기반 컴포넌트
- 차트 라이브러리: 통계 데이터 시각화를 위한 라이브러리
